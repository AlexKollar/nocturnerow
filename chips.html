NAVI'S TOOLS — CHIPS

Chips.

Her hands, in cartridge form. A chip is a tool Navi runs herself — packaged as a .png cartridge that carries its code and its metadata in the cartridge itself, the way a PICO-8 cart carries a game, with Battle Network in its blood.

Navi's Tools SHIPPED · Apex Edge v0.6.8e

What a chip is

Chips are distinct, in-house tools — not plugins bolted onto a chat window, but instruments she picks up and runs. She reaches for them from chat, in the flow of the work: a scan mid-case, a crypto job mid-conversation, answered with the tool's real output in the thread. They are also runnable from the bottom pill row, by hand, when the operator wants the tool without the conversation. Either way, the chip that runs is the same cartridge.

None come pre-installed, deliberately. A fresh Apex carries no cartridges at all — her hands grow by her operator's choices, one install at a time, and the shelf she grows from is public.

The in-app NUR — finding and installing

Inside Apex, the Navi User Repo is where chips are browsed and installed. Chip Management searches GitHub by the navi-chips topic, so the shelf is every published cartridge — no app store, no gatekeeper, no separate errand. Installing one is an operator act: Navi can find, describe, and recommend, but the cartridge lands in her deck because her operator put it there.

The NUR — the shelf's public face The chip shelf on GitHub

Chip Studio — making them

Chips are not only found; they are made. Chip Studio is the creation and editor surface inside Apex: author a chip, shape what it does, and package it as a cartridge — without leaving the app, without a separate toolchain, without handing the work to some other program and hoping it comes back in the right shape. The Studio is where a tool she needed once becomes a tool she keeps.

The release cycle, built right in

A chip lives as a GitHub repository under the navi-chips topic, and the whole of its life runs through Apex's own machinery. Chip Studio publishes and releases the cartridge; every other seat discovers it through the same topic search the NUR already runs; an update is simply a new release of the cartridge, found the same way the original was. Author → release → discover → install → update — the full cycle happens inside the app, with GitHub as the shelf it all stands on. Nobody emails anybody a zip file.

ON THE HORIZON — CHIPS EXPANDED

Designed, not built

Nothing in this section ships today. It is the chips layer's next era, on paper:

The trust wall

Provenance and digest on the cartridge itself; install and update become trust events, named as such — a cartridge is believed because its papers check out, not because it was easy to fetch.

Declared capabilities

A chip declares what it needs, and the system grants exactly that: chips gain nav rail items and UI elements of their own, register their own surfaces, and modify the system as a whole — under the grant, never around it.

A designer in the Studio

Chip Studio gains a drag-and-drop UI designer that rigs the code up as the surface is drawn — the editor growing from code-first to shape-first.

Case-born chips

A case runs as two detectives telling the story of the evidence, and tools get hacked together mid-case as it demands. Those tools graduate: the case file is the chip's birth certificate, and the cartridge joins the shelf. Case Files is where they are born.
