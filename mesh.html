APEX | MESH — THE ROADS BETWEEN THE MACHINES

Many machines. One mind.

The Mesh is one federated whole: every device attached to it serves the goal of whoever is using Apex, in whatever form factor. A distributed network that functions like a neural net — the more nodes on it, the faster the smallest, least powerful system on it can think.

The Mesh, drawn

● the ask — a prompt leaves the smallest node  ·  ● the answer — the fleet's work comes home. The drawing is the design target; the status line at the top is tonight's truth.

How the Mesh works

A handshake, not an account

Nodes pair by exchanging cards — a picture, carried by hand. No cloud directory, no account, no landlord in the middle. Each node keeps its own ledger of exactly who it trusts, and trust is pairwise: my friend is not automatically yours.

The ask goes out whole

When a node needs more muscle than it has, it sends the whole request to a stronger peer it trusts, and the answer comes back the same road. That is borrow, and it already ships: a small box thinks at the speed of the biggest machine on the Mesh.

The answer is a federation

Ring 2 — designed in the open, building now in the 0.2.0e line — splits work into tasks the fleet shares. A sensor like Pia can put a prompt to the whole Mesh at once: Neo-Arcadia and Neon Drip each contribute, and she receives one composed answer. The more nodes join, the faster the smallest node in the house gets.

Bring a node

Node № 004 is deliberately empty. The Mesh grows the way trust actually grows: one machine at a time, paired by hand. Run Apex on a box you own, exchange pairing cards with a node whose operator you trust, and your smallest hardware stops being your ceiling — every stronger machine on your roads answers for it.

No account to open. No subscription to keep. Nothing to phone home to, because home is the address.
